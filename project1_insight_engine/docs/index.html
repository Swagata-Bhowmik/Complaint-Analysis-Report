The idea
Companies get thousands of complaints written in plain English. Nobody can read them all, so they never learn what's really wrong. This tool reads them for you and produces a clear, ranked list: "here are the top problems, fix these first."
Golden rule: real public data only, no fabrication — every number here traces back to a real complaint and can be defended step by step.

🎯 The Problem & The Goal

Why this project exists and what success looks like.

😖 The pain
A bank or big company receives thousands of complaints every week — double charges, fraud, app failures, rude service. Reading them one-by-one is impossible, so the most valuable information — what is actually going wrong — stays buried, and managers react only to whoever shouts loudest.
🎯 The goal
Automatically answer three questions: (1) What are people complaining about? (2) Which problems matter most (common × severe)? (3) So what should we fix first?
💼 Business value
Turning raw text into a ranked action plan means fixing the right things first — saving money, reducing churn, improving trust.

📚 What we used
The CFPB Consumer Complaint Database — a free, public U.S. government dataset of real complaints. The key field is the narrative: the customer's own written story of what happened.
🧭 Why this (and not scraping app reviews)
Scraping violates platform terms, is unreliable, and raises privacy issues. "Publicly visible" ≠ "safe to bulk-collect." CFPB is legal, large, and defensible.
🔬 What profiling taught us
Narratives only exist from 2015 onward; the same product had multiple labels over the years; and we caught a silent bug where dates were corrupted during extraction — a chart looked wrong, we investigated, and fixed it. Proof you must sanity-check everything.

🧯 Problems found
~12,000 duplicate complaints (inflate counts); privacy masks everywhere (XXXX, XX/XX/year>, {$70.00}); two names for the same product.
🧼 What we did
Removed duplicates, merged product labels, and turned privacy masks into neat placeholders (<redacted>, <date>, <money>) instead of deleting them — keeping sentences readable. Original text kept too, for before/after auditability.
Before: "In XX/XX/year>, XXXX applied charges higher than I agreed…"
After: "In <date>, <redacted> applied charges higher than I agreed…"

🧠 The AI Engine

How the computer "reads" complaints and finds problems — in 5 steps.

🧠 1 — Embeddings
Each complaint becomes a list of 384 numbers capturing its meaning, so similar complaints sit close together on a "meaning-map". Tool: sentence-transformers, model all-MiniLM-L6-v2.
🧩 2 — Clustering
KMeans finds the crowds of dots on that map — each crowd is a theme. We used K=12.
⚠️ 3 — Severity
How bad is each problem? We score negativity with VADER and flag high-stakes words (fraud, stolen, identity theft).
🏆 4 — Priority
Priority = Volume × Severity — surfaces problems that are both common AND serious.
🏷️ 5 — AI naming
An LLM (Google Gemini) reads each theme's keywords + examples and gives it a clear human name.
TF-IDF → theme keywords PCA → 2D meaning-map Caching → embed once, reuse

🛠️ Tools & Tech — explained simply

Every technology used, in plain words.

Python — the language everything is written in.
pandas / Parquet — work with data tables; Parquet is robust for messy text.
sentence-transformers (all-MiniLM-L6-v2) — turns text into 384-number meaning-vectors.
KMeans (scikit-learn) — groups the vectors into themes.
TF-IDF — finds each theme's distinctive keywords.
PCA — shrinks 384 dimensions to 2 for plotting.
VADER — fast sentiment scoring for severity.
Google Gemini (LLM) — names each theme in plain English.
Streamlit + Plotly — turn the pipeline into an interactive app & charts.
Git / GitHub — version control + public portfolio.

🎓 Discoveries & What I Learned

The honest lessons — great for interviews.

🐞 Trust nothing unverified
A time chart looked flat/wrong. Investigating revealed dates were silently corrupted during extraction. Fixed it and switched to Parquet. Always sanity-check a result that looks off.
📈 More data, cleaner themes
On an 18k sample, "fraud" spread across several overlapping clusters. On the full 112k, themes separated cleanly. More data reduces clustering noise.
🥇 Fraud dominates
The #1 problem — unauthorized/fraudulent charges — is both the most common (13.4%) and most severe.
🧪 Validate everything
Checked after every step (completeness, duplicates, valid dates, sane labels) with a reusable check, showing real before/after examples — never just summary numbers.
